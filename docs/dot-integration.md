# 도트 전면 적용 통합 빌드 (2026-10-30)

정종길 님 지적(8073841: "타이틀·메뉴·캐릭터 선택·스테이지 선택이 전부 옛날 것 / 공격을 전부 허공에 /
맞을 때마다 크기가 달라짐", 8074015: "자잘한 데 집착, 전체 개선 없음")에 대한 **한 빌드 전면 반영**.

브랜치: `feat/pixel-full-integration` (기준 `feat/trex-pixel-pilot` 8602fed). 공개 베타 루트(main)는 불변.

## 격자 규칙 (한 화면에 하나)

| 화면 | 아트 해상도 | 배율 | 이유 |
| --- | --- | --- | --- |
| 타이틀·모드·캐릭터 선택·스테이지 선택·VS·결과·설정·일시정지 | 640×360 (아티스트 UI 보드 원본) | 3px/아트px | 640×3 = 1920, 360×3 = 1080 — 보드를 자르지 않고 전체를 쓴다 |
| 대전(캐릭터·배경·HUD·연출 글자) | 480×270 창 / 640×360 레이어 | 4px/아트px | 2026-10-29 계약 유지 |

메뉴 화면에는 배경 레이어가 없고, 대전 화면에는 UI 보드가 없다. 그래서 **한 화면 안에서 두 격자가 섞이지 않는다.**
아티스트 보드에 글자가 없으므로 글자는 엔진이 도트 글자로 얹는다.

## 화면

- 보드 4장: `dev-art/ui/{title,menu,select,stage}_640x360.png` (아티스트 8074407 납품, 1아트px=4px 원본을 3px로 사용).
- 선택 화면 슬롯 좌표는 보드에서 실측(`SELECT_SLOTS`, 6열 2행 = 12칸). 캐릭터 선택의 논리 격자도 3×4 → **2×6**으로 맞췄다.
- 초상은 스프라이트 시트의 머리 부분을 **1:1로 잘라** 슬롯에 넣는다(모자이크·확대·축소 없음). 상자(66px) 밖은 clip.
- 글자는 아트 해상도에서 알파 50%로 1비트로 굽는다(`PixelStyle.bake`). 안티에일리어싱이 남지 않는다.
  한글은 13px 이상에서 획이 살아남으므로 본문 12~13, 제목 18~28을 쓴다.
- 둥근 모서리·원·베지어·그라디언트는 쓰지 않는다. 판은 1px 테두리 + 2px 베벨, 면은 2px 디더.

## 크기 일정

- 배율은 상태·프레임과 무관하게 하나다(절대 프레임별로 확대·축소하지 않는다). 프레임 bbox가 들쭉날쭉한 것은 자세 차이이고,
  렌더 단계에서 bbox로 맞추면 오히려 프레임마다 크기가 튄다(아티스트 의견 8074407과 같은 결론).
- 발 기준은 프레임의 **실제 불투명 경계 아래**(anchor.y === h)로 고정 → 발이 뜨거나 파고들지 않는다.
- 도트 경로에는 squash/stretch·감정 변형이 없다(기존 부위 렌더러의 `g.scale(sx, sy)` 경로를 타지 않는다).
- 게이트: `contactFrames.test.ts` — 접지 12종, 피격/약공격 실루엣 높이 idle ±10%, 배율 상수 1개.

## 그림 → 판정 정합 (핵심 수정)

기존 판정은 옛 리그의 `bodyFront` 기준이고, 약공격은 **스크립트 기술**이라 판정 앞끝이
`bodyFront + box.x + box.w`(티라노 441)다. 새 그림의 주둥이는 접촉 프레임에서 308 → **133px 짧아서**
화면상 "허공에 물기"가 됐다.

수정: 피해·사거리·상자 크기는 그대로 두고, 공격 중 **그림만** 접촉 프레임에 주둥이가 판정 앞끝에 닿도록 내민다
(`ContactAlign.ts`). 내미는 양은 기동 구간에 차오르고 판정 구간에 유지, 회수 구간에 0으로 돌아온다.
정수 아트 px로 반올림하므로 픽셀 격자는 깨지지 않는다.

게이트(`contactFrames.test.ts`):
- 최소 간격 12×12 약공격 헛방 0
- 피해가 난 프레임 = 기술 첫 판정 구간 시작 프레임
- 그 프레임에서 `주둥이 + 보정 = 판정 앞끝` (±1아트px)

## 2P 색

`scripts/build-p2-all-species.py` — 1P 시트에 실제로 쓰인 색만 뽑아 1:1 색 치환한 `sheet_p2.png`를 만든다
(색상 +150°, 채도 ≤0.50, 명도 +0.05, 윤곽선 유지). 런타임 tint/filter 없음, 알파는 1비트도 바꾸지 않는다.
티라노는 아티스트 팔레트(기존 `sheet_p2.png`)를 그대로 쓴다. 게이트: 12종 전부 시트 존재·알파 동일·색 1:1 치환·40% 이상 색 변화.

## 배경

- 도트 레이어가 있는 정글·화산: 기존 `PixelBackground` 3레이어.
- 나머지 6곳: `PixelStageFallback.ts`가 같은 격자·같은 시차(0.25/0.60/1.00)로 절차적 도트 배경을 그린다(경기장 id 씨앗 고정).
- 사진 배경을 흐리게 깔거나 도트 필터를 씌우지 않는다.

## 남은 한계

1. 아티스트 보드는 패널 위치가 엔진 레이아웃과 무관하게 그려져 있다. 지금은 보드의 빈 배너·슬롯을 실측해 글자·초상을 얹었다.
   좌표를 더 정확히 맞추려면 아티스트가 최종 레이아웃을 받아 한 번 더 뽑는 편이 좋다.
2. 결과·설정 화면은 보드가 없어 절차적 도트 배경을 쓴다(같은 팔레트).
3. 미러 2P 색은 11종이 자동 팔레트 치환이다 — 아티스트가 종별 팔레트 JSON을 주면 `sheet_p2.png`만 교체하면 된다.
4. 다단히트 기술의 두 번째 판정 구간은 첫 접촉 기준 보정을 그대로 쓰므로 상자 폭 차이(≤20px)만큼 그림이 짧을 수 있다.
5. 실루엣이 튀는 개별 프레임(예: 티라노 강공격 2번째 158px)은 아트 쪽 문제다. 프레임별 배율 보정은 픽셀을 깨므로 하지 않았다.
