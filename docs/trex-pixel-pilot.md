## 아티스트 계약

TypeScript: `src/rendering/pixel/PixelAnimation.ts`의 `PixelManifest` / `PixelFrame` / `PixelClip`.
실행 검증: `parsePixelManifest`, `validatePixelImage`, `validateBiteTiming`.
JSON 예시: `docs/pixel-manifest.example.json` — **좌표/타이밍 계약 예시일 뿐 PNG 아트가 아니다**.

예시는 192×128 셀 26장(4/8/8/3/3), 4열 768×896 시트다. 크기와 프레임 수는 조정 가능하다.
모든 좌표는 원본 픽셀 정수, `anchor`는 각 프레임 잘라낸 영역 안의 발/몸 기준점이다.
모든 장면의 캐릭터 크기와 팔레트, 측면 방향, 접지 기준을 아트 단계에서 일관되게 맞춘다.
`scale`은 모든 프레임 공통 1~8 정수배. 프레임별 fit, 회전, 파츠 변형, 모자이크 필터 없음.
`facing`은 원본이 보는 방향이다. 게임 facing에 따라 발 기준에서 좌우 반전한다.
Canvas 내부는 nearest-neighbor와 정수 목적 좌표를 쓴다. 최종 1920×1080 게임 캔버스의 CSS 반응형 축소는 별도이며 기기 화면에서 정수배라고 보장하지 않는다.

연결 방법:
1. 패널에서 로컬 JSON + PNG를 선택해 연결(서버에 업로드하지 않음). 장면 종료 후 참조 정리.
2. 현재 `dev-art/tyrannosaurus/manifest.json` + PNG를 자동 연결한다. 실패하면 기존 그림 유지, `저장된 아트 연결/재시도`로 재시도한다.
   `dev-art/`는 public 바깥이며 production dist에 복사되지 않는다. 아트는 DEV 진입 시에만 읽는다.
잘못된 JSON, 순서/시간/앵커/시트 크기/이미지 실패는 도트 연결을 거부하고 기존 렌더러를 유지한다.

## 실제 전투와 물기 접촉

**약공격 `tyrannosaurus_light`만** bite에 연결한다. 기존 기술은 30틱 동안 2회 문다.
실제 피해 가능 창은 스크립트 `hits`의 **6–8틱, 12–15틱**(0-based, 60Hz).
`biteContactFrames[0/1]`은 각 창에서 보여 줄 접촉 그림의 시트 프레임 ID다.
해당 창 전체에서 일치하는지 로딩 때 검사한다. 예시는 frame14/16을 사용한다.
그림 순서/시간을 이 창에 맞추며 **피해 시점을 그림에 맞춰 바꾸지 않는다**.
접촉 창이 켜져도 상대가 범위 밖이면 피해는 없다. 이미지가 닿아 보이는 공간과 기존 hitbox의 일치 검수는 남아 있다.
v1 원본은 한 번 무는 8장이다. 전투 어댑터는 같은 접촉 그림(원본 1-based 4번=전체 frame15)을 두 번 사용한다.
전투 순서(원본 0-based 번호/틱): 0/2,1/2,2/2,3/3,1/1,2/2,3/4,4/3,5/4,6/4,7/3. 총30틱.
이는 명시적 **비교용 재타이밍**이며 새로 그린 자연스러운 2연속 물기가 아니다. 9틱→10틱 재준비/입벌림이 빠르므로 전용 2연속 시퀀스가 후속 후보다.
~~강공격 잡기(성공/실패 프레임 점프), 특수기, 점프/방어/승리 등은 기존 렌더러로 명시적 fallback.~~
→ **폐기(2026-10-29)**: 도트 화면에서는 어떤 상태도 파츠 렌더러로 넘기지 않는다. 위 "전신 1프레임 규칙" 절 참고.

대기/걷기는 반복, 피격/다운은 마지막 프레임 유지. 다운 상태 전환 시 처음부터 재생한다.
매 시뮬레이션 스텝 전 정지 여부를 캡처하고 이후 상태를 관찰한다.
피격이 발생한 바로 그 틱에는 피격 첫 장으로 전환하고, 정지 마지막 틱(1→0)까지 유지한다.
공격은 별도 wall clock이 아니라 `fighter.attack.frame`을 직접 샘플하므로 히트스톱·공격 ID·프레임 전환에 맞는다.
일시정지 때 BattleScene 자체가 step하지 않으며, 새 라운드에는 애니메이터를 초기화한다.

## 배율 계약: 아트 1px = 화면 4px (jk 확정 2026-10-29)

캐릭터를 배경·격자에 맞추려고 3배로 낮추던 것을 되돌렸다. 순서는 반대다 — 배경을 캐릭터에 맞춘다.
캐릭터·배경 모두 아트 1px = 화면 4px이고, 12종 재작화도 판정 축소도 하지 않는다.

- `PIXEL_ART_SCALE = 4`, 창(화면에 보이는 아트 범위) `PIXEL_VIEW_W/H = 480×270` (= 1920×1080 ÷ 4).
- `pixelScaleFor(width)` = `width / 480` (정수일 때만). 1920×1080 → 4.
- 배경 레이어는 640×360 아트 px를 그대로 4배로 그린다(2560×1440). 창보다 큰 것이 정상이며,
  창은 레이어 가운데(x 80~560, y 73~343 아트 행)를 보여 준다. 지면선 standLine 298 → 화면 y 900.
- 레이어 원점·스프라이트 원점을 모두 배율 격자(4의 배수)에 맞춘다. 그래야 캐릭터 블록과 배경 블록이
  같은 격자 위에 놓인다(반 칸 어긋나면 확대 시 블록 경계가 흔들린다).
- 시차 이동량은 게임 좌표 기준 그대로(계수 0.04/0.14/0.30 → 최대 ±12/42/90 아트 px). 레이어 여백
  (±80/128/176 아트 px, pad 160/48/96) 안이므로 클램프에 걸리지 않는다. pad 없는 640 레이어는
  지면 여백이 ±80으로 부족하다 — 지면·중경은 반드시 블리드판을 쓴다.
- 배경 로딩 버그 수정: 이미지를 `폴더/파일` 전체 경로로 보관해 두고 파일 이름으로 찾아 항상 실패했다
  (조용히 기존 벡터 배경으로 넘어감). 이제 경로로 찾으며, 로딩→3레이어 실제 그리기를 검사하는
  회귀 테스트가 있다.

## 2차 확정: 시차·판정 크기·시작 간격 (jk 지시 2026-10-29)

### 시차 계수 0.25 / 0.60 / 1.00
- 지면이 1.00이라야 접지한 발이 지면 위를 흘러가지 않는다(0.30이면 지면이 캐릭터 이동의 30%만 따라온다).
  카메라 중심 = 두 캐릭터 중점이고, 지면 레이어는 중점 이동과 1:1로 움직인다.
- 레이어 그리기 원점·시차 이동량은 모두 4px 배수로 스냅한다(`drawCenteredLayer`, `snapToScale`).
  0.25/0.60 계수는 소수라 1~3px 어긋나면 4px 격자가 깨지기 때문이다.
- 여백 검증: 앞끝이 화면에 남는 이동 범위(중점 ±536)에서 필요한 이동은 원경 34 / 중경 80 / 지면 134 아트px이고,
  아트 여백은 240 / 128 / 176 아트px이다(테스트 `displayHeightLock.test.ts`가 고정).
  지면·중경은 블리드판(pad 96/48)이 필수다.

### displayHeight lock
- 판정·몸 크기 기준 `displayHeight` = 그 종의 **아트 대기(idle) 실루엣 최대 키 × 4**.
  `src/rendering/pixel/displayHeightLock.test.ts`가 dev-art 시트 PNG를 zlib로 직접 풀어 재측정하고 비교한다
  (아트가 바뀌면 테스트가 먼저 깨진다 — 그림만 갈고 판정을 두는 일을 막는다).
- 값: 티라노 436 · 트리케라 360 · 벨로키 344 · 스피노 424 · 안킬로 328 · 스테고 408 · 카르노 428 ·
  파키 388 · 테리지노 448 · 딜로포 376 · 브라키오 608 · 프테라 348.
- 부수 효과(측정): 트리케라가 368→360으로 줄어 돌진 사거리 1590→1580, 뒤로 빠지는 상대에게 두 번째 물기가
  닿지 않아 가드 이벤트 2→1. 티라노 약공격 2연타는 두 번째 물기 x를 62→70으로 보정해 유지했다
  (250~540 간격 전부 2타, 700은 헛방).

### 시작 간격 · 속도
- 시작 간격 966(중점 기준 ±483, 477/1443): 주둥이 앞끝 사이 313px(목표 300~360).
- 이동 속도 360→356 디자인px/s = 89 아트px/s × 4 (아트 걷기 8아트px/90ms).
